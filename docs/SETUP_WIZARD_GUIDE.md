# OpenDR Setup Wizard Guide

The `opendr-setup` utility provides an interactive wizard for first-time server configuration, including replication setup.

## Quick Start

### Interactive Setup

Run the interactive wizard:

```bash
opendr-setup interactive
```

The wizard will guide you through:
1. Basic directory configuration (Base DN, organization)
2. Administrator credentials
3. Network settings (LDAP/LDAPS ports)
4. Storage backend selection
5. **Replication configuration** (new!)
6. Sample data import

### Non-Interactive Setup

Generate a sample configuration file:

```bash
opendr-setup generate-config --output my-config.toml
```

Edit the file and run:

```bash
opendr-setup non-interactive --config my-config.toml
```

## Replication Setup Walkthrough

### Setting Up a Provider (Master) Server

When you reach the replication configuration section:

```
╔════════════════════════════════════════════════╗
║        Replication Configuration              ║
╚════════════════════════════════════════════════╝

Enable replication? (yes/no) [no]: yes

Select replication role:
  1. Provider (Master) - Source of directory data
  2. Consumer (Replica) - Receives updates from provider
Enter your choice [1]: 1

--- Provider Configuration ---
Enable changelog tracking? (yes/no) [yes]: yes
Maximum changelog entries [100000]: 200000
Maximum batch size (entries per sync) [100]: 100
Enable real-time streaming? (yes/no) [yes]: yes
```

**Provider Configuration Options:**

- **Changelog tracking**: Enables tracking of all directory changes
  - Default: Yes
  - Recommendation: Always enable for replication

- **Maximum changelog entries**: Number of changes to keep in memory
  - Default: 100,000
  - Increase for busy directories or infrequent consumer syncs
  - Range: 10,000 - 1,000,000

- **Maximum batch size**: Entries sent per synchronization batch
  - Default: 100
  - Increase for high-bandwidth networks
  - Decrease for slow/unreliable connections
  - Range: 10 - 1,000

- **Real-time streaming**: Send changes immediately to consumers
  - Default: Yes
  - Disable for polling-only replication

### Setting Up a Consumer (Replica) Server

When you reach the replication configuration section:

```
╔════════════════════════════════════════════════╗
║        Replication Configuration              ║
╚════════════════════════════════════════════════╝

Enable replication? (yes/no) [no]: yes

Select replication role:
  1. Provider (Master) - Source of directory data
  2. Consumer (Replica) - Receives updates from provider
Enter your choice [1]: 2

--- Consumer Configuration ---
Provider URL (e.g., ldap://provider.example.com:389) [ldap://provider.example.com:389]: ldap://10.0.1.100:389
Authenticate to provider? (yes/no) [no]: yes
Provider bind DN [cn=replication,dc=example,dc=com]: cn=replication,dc=example,dc=com
Provider bind password: ********
Synchronization interval (seconds) [30]: 30
Maximum retry attempts [3]: 5
Enable continuous change listening? (yes/no) [yes]: yes
Replication state storage path [./data/replication_state]: /var/lib/opendr/repl_state
```

**Consumer Configuration Options:**

- **Provider URL**: LDAP URL of the provider server
  - Format: `ldap://hostname:port` or `ldaps://hostname:port`
  - Example: `ldap://provider.example.com:389`

- **Authentication**: Credentials for connecting to provider
  - Optional but recommended for security
  - Requires a dedicated replication user on provider

- **Sync interval**: How often to check for changes (seconds)
  - Default: 30 seconds
  - Decrease for near-real-time replication
  - Increase to reduce network traffic
  - Range: 5 - 3600

- **Retry attempts**: Number of retries on failure
  - Default: 3
  - Increase for unreliable networks

- **Continuous listening**: Stay connected for real-time updates
  - Default: Yes
  - Requires streaming enabled on provider

- **State storage path**: Where to save replication state/cookies
  - Must be persistent across restarts
  - Allows resume from last sync point

## Complete Setup Example

### 1. Setup Provider Server

```bash
# On provider machine (10.0.1.100)
opendr-setup interactive

# Follow prompts...
# Base DN: dc=company,dc=com
# Admin DN: cn=admin,dc=company,dc=com
# LDAP Port: 389
# Backend: LMDB
# Data directory: /var/lib/opendr/data
# Replication: Yes
# Role: Provider
# Changelog: Yes (200000 entries)
# Batch size: 100
# Streaming: Yes

# Start the provider
opendr-server start
```

### 2. Create Replication User on Provider

```bash
ldapadd -x -H ldap://10.0.1.100:389 \
    -D "cn=admin,dc=company,dc=com" \
    -w admin_password <<EOF
dn: cn=replication,dc=company,dc=com
objectClass: simpleSecurityObject
objectClass: organizationalRole
cn: replication
userPassword: repl_secret
description: Replication service account
EOF
```

### 3. Setup Consumer Server

```bash
# On consumer machine (10.0.1.101)
opendr-setup interactive

# Follow prompts...
# Base DN: dc=company,dc=com
# Admin DN: cn=admin,dc=company,dc=com
# LDAP Port: 389
# Backend: LMDB
# Data directory: /var/lib/opendr/data
# Replication: Yes
# Role: Consumer
# Provider URL: ldap://10.0.1.100:389
# Auth: Yes
# Bind DN: cn=replication,dc=company,dc=com
# Bind Password: repl_secret
# Sync interval: 30
# State path: /var/lib/opendr/repl_state

# Start the consumer
opendr-server start
```

### 4. Verify Replication

```bash
# Add entry on provider
ldapadd -x -H ldap://10.0.1.100:389 \
    -D "cn=admin,dc=company,dc=com" \
    -w admin_password <<EOF
dn: cn=Test User,dc=company,dc=com
objectClass: person
cn: Test User
sn: User
EOF

# Wait ~30 seconds, then check consumer
ldapsearch -x -H ldap://10.0.1.101:389 \
    -b "dc=company,dc=com" \
    "(cn=Test User)"
```

## Advanced: Non-Interactive Configuration File

Create `setup-config.toml`:

```toml
base_dn = "dc=company,dc=com"
root_user_dn = "cn=admin,dc=company,dc=com"
root_password = "SecurePass123"
ldap_port = 389
ldaps_port = 636
hostname = "ldap.company.com"
organization_name = "Company Inc"
backend_type = "Lmdb"
data_directory = "/var/lib/opendr/data"
import_sample_data = false

[replication]
enabled = true
role = "Consumer"

[replication.consumer]
provider_url = "ldap://provider.company.com:389"
provider_bind_dn = "cn=replication,dc=company,dc=com"
provider_bind_password = "repl_secret"
sync_interval_secs = 30
max_retry_attempts = 3
retry_delay_secs = 5
enable_change_listening = true
state_storage_path = "/var/lib/opendr/repl_state"
```

Run setup:

```bash
opendr-setup non-interactive --config setup-config.toml
```

## Troubleshooting Setup

### "Server already configured" Error

Reset the configuration:

```bash
opendr-setup reset
```

Or force reset without confirmation:

```bash
opendr-setup reset --force
```

### Check Configuration Status

```bash
opendr-setup status
```

### Validate Configuration File

The setup wizard validates:
- Password strength (8+ chars, uppercase, lowercase, digits)
- Port numbers (1-65535)
- DN format
- Replication role consistency
- Directory paths

## Best Practices

1. **Use Strong Passwords**
   - Minimum 8 characters
   - Mix of uppercase, lowercase, and numbers
   - Consider using password managers

2. **Provider Setup**
   - Set changelog capacity based on change rate and sync frequency
   - Enable streaming for real-time replication
   - Monitor changelog size in production

3. **Consumer Setup**
   - Use dedicated replication credentials
   - Choose sync interval based on replication lag requirements
   - Ensure state storage path is persistent

4. **Security**
   - Use LDAPS (TLS) in production
   - Restrict replication user permissions
   - Different credentials for each consumer

5. **Testing**
   - Test replication before production deployment
   - Verify failover and recovery procedures
   - Monitor replication lag
